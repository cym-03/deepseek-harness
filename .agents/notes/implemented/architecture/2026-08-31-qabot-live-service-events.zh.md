# Agent Note：Qabot 服务台变更实时推送

状态：已实现

[English](2026-08-31-qabot-live-service-events.md) | 中文

## 问题

员工会话页和客服工单工作区每两秒轮询完整列表与当前详情。人工回复显示存在延迟，空闲页面会持续产生数据库和 HTTP 流量，同时轮询还可能在模型回答流式生成期间覆盖前端乐观状态。

## 决策

Qabot 提供一个经过身份认证的 `GET /v1/events` SSE（Server-Sent Events）事件流。Repository 写入完成后，工单变更会发布进程内单调递增版本。事件只表达“数据已变化”，不携带完整消息；门户继续通过现有版本化接口重新加载有权访问的列表和当前详情，这些读取接口仍然负责响应字段与权限校验。

事件只携带过滤所需的员工标识、服务组、处理人和版本。员工只接收本人身份的变更；系统管理员接收全部变更；其他服务台身份接收当前服务组或处理人为本人显示名称的变更。NestJS BFF 为上游身份签名并透传字节流，浏览器 `EventSource` 负责自动重连。Qabot 发送注释心跳，并在客户端连接关闭时移除监听器。

原有模型回答流保持独立，因为它为一次提问传输有序回答增量、引用、转人工建议、完成与错误。服务台实时事件流只替代员工消息和工单轮询。

## 考虑过的替代方案

- **保留两秒轮询：** 不采用，因为延迟和后台负载会随打开的员工页与客服页数量增长。
- **在变更事件中发送完整会话：** 不采用，因为这会在读取接口之外重复权限与时间线投影。
- **使用 WebSocket：** 暂缓，因为当前链路只有服务端到浏览器的失效通知，浏览器管理重连的 SSE 已足够。

## 结果

员工消息、接单、转派、关闭和评分现在无需固定轮询即可立即刷新。连接丢失后浏览器会自动重连，下一次事件会重新读取权威状态。事件版本只是进程内失效标记，不是持久游标；重连不会补发错过的事件，因此页面仍会在挂载和自身操作完成后读取当前状态。
