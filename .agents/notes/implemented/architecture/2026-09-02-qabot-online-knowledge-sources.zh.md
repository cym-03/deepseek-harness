# Agent Note: 将 Qabot 知识作为同步在线来源管理

Status: implemented

[English](2026-09-02-qabot-online-knowledge-sources.md) | 中文

## Problem

Qabot 把文档提交、审核、版本差异、发布时段、下架状态和删除拆成多个后台操作。这套流程不符合持续编辑的飞书在线文档，并且生产知识源配置仍保存在主机本地 JSON 文件中。

## Decision

MySQL `knowledge_sources` 是知识源注册表的权威源。每条记录保存标题、不可修改的飞书链接、维护分组、提交人身份、同步状态、最近成功同步时间、最近错误和可选的移除时间。现有来源迁移到 `other` 分组，提交人记为 `system-migration`。

维护分组固定为 `hr`、`admin`、`it`、`finance` 和 `other`。所有活跃来源仍面向全体员工问答。服务台人员只能维护本人所属组的来源，SystemAdmin 可以维护全部来源。提交人员工 ID 和真实姓名取自门户签名身份。同步只使用该提交人的飞书用户授权，不回退到机器人、主管或其他员工身份。

新增来源会触发首次同步。只有首次同步成功后，文本、普通图片和嵌入画板才进入检索。画板按块中的稳定 token 建立独立视觉资产，并使用所在章节作为检索说明；所有派生文档和资产仍按[派生知识文档归属于提交的在线知识源](../bug-fix/2026-09-04-derived-knowledge-documents-belong-to-online-source.md)由已提交来源统一持有。每次同步都会重新导出画板快照；配置的 OCR 模型把新增或变化画板中的可见文字写入该画板的可检索知识块，素材哈希未变化时同时复用识别文字和视觉向量，不再请求模型。快照变化时替换当前素材，并重新计算识别文字和一个新向量。密集 OCR 输出仅在整图达到配置上限后拆成重叠区域；空白区域不产生文字，最小区域会保留不完整结构化响应中已经完整返回的文字字段。此后由五分钟定时任务和单行立即同步操作执行增量同步。文档内容未变化时复用现有向量；内容变化时建立内部版本，在同一次投影事务中归档此前所有已发布版本，并原子替换当前可检索内容。检索还会独立限定每份文档中版本号最大的已发布版本，使异常的历史状态无法混合新旧内容。内部版本只用于安全替换和向量复用，不向后台人员展示。

首次同步失败时保留来源记录，但不参与召回。后续同步失败时继续使用上一次成功内容，并在来源上记录错误。软移除会停止调度，并立即把该来源的文档、文本向量、视觉向量和图片排除出检索。重新添加相同规范化链接时恢复原记录，并可复用未变化的索引数据。

门户使用紧凑来源表格，提供标题搜索、维护分组筛选、健康汇总、单来源同步状态、最后同步时间，以及编辑、同步和移除操作。点击来源标题会打开原文。门户不再调用或展示审核、版本差异、发布、驳回、生效时段、下架或独立删除流程。来源变更和同步结果继续写入现有审计流。

系统接受 Docx、飞书电子表格和多维表格的直接链接，知识库节点也可以解析为这些类型。电子表格使用提交人令牌分块读取单元格，并保存为包含工作表名、列表头和每行字段名的可检索记录。直接电子表格链接指定一个工作表时，只建立该工作表的索引。

## Alternatives considered

- **保留审核和发布步骤：** 拒绝，因为这些受控文档面向全体员工，业务维护者需要同步在线内容，而不是执行版本发布管理。
- **立即使用飞书事件回调：** 本阶段拒绝，因为五分钟轮询与手动同步可以满足新鲜度要求，不需要再配置一个外部集成。
- **硬删除已移除来源：** 拒绝，因为软移除保留审计能力，并允许恢复未变化的来源时复用索引数据。
- **引入 Milvus：** 拒绝，因为当前数据规模和 MySQL 向量持久化尚不足以证明新增生产依赖的必要性。
- **逐份文档授予机器人权限：** 拒绝，因为来源访问权限属于提交该来源的员工，而且逐文档授权无法随文档数量扩展。

## Consequences

后台人员维护一条持久知识源记录，不再处理提交和发布流程。生产知识源的列出、鉴权、同步和移除都依赖 MySQL 可用。本地录入数据库只保留为可重建工作索引，不能单独激活来源。

未手动同步时，来源变化最长五分钟后进入问答；部署启动器保留这个五分钟周期，不另行覆盖。门户在 OAuth 登录时申请文档、媒体、画板和离线刷新范围，把每位提交人的可续期凭证加密保存到 MySQL，按需刷新，并通过受鉴权的内部接口只向 Qabot 提供短期访问令牌。内嵌图片要求已发布的飞书应用具有 `docs:document.media:download`，嵌入画板要求 `board:whiteboard:node:read`，并且提交人仍可访问来源。普通图片请求会携带父 Docx 上下文，并降级尝试飞书原始素材预览流和临时链接；画板通过图片导出接口获取当前快照。原始素材继续保存用于展示，SVG 画板会规范化为 PNG，只有超过模型请求限制的素材会生成缩放压缩副本用于 OCR 和向量化。MySQL 投影会以稳定 ID 更新未变化的视觉素材，使持久会话引用持续有效。OCR 输出会拆成普通知识分块。整图或外层分区达到配置输出上限时会继续拆分而不直接入库；只有最小分区在服务未返回结构化结尾时，才会保留其中已经完整返回的文字字段。视觉检索会返回高置信结果或相互印证的较低分结果组，并拒绝单个弱匹配。匹配的视觉素材会作为卡片附在回答后，画板识别文字则通过普通知识检索提供给回答模型。授权缺失或过期时继续使用上次成功内容，并在来源上记录错误；未取得的视觉素材不会调用 OCR 或视觉向量模型。SystemAdmin 再次提交活跃 `system-migration` 来源的链接或对其执行立即同步时可以认领该来源，普通活跃重复来源仍会被拒绝。保留的内部版本和历史审核表只属于实现历史，不再是后台产品概念。
