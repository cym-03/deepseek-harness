# Agent Note: 使用门户身份认证 Qabot 请求

Status: implemented

[English](2026-08-27-qabot-signed-identity-and-session-serialization.md) | 中文

## Problem

原型 API 从请求体接收员工和处理人标识，并使用一个共享令牌保护全部操作。任何持有令牌的调用方都能选择其他员工的会话；同时访问同一 DSH 会话的回合也可能重叠，使输出归属错误请求。

## Decision

版本化员工 API 从 `Authorization` 请求头接收短时门户身份。门户将身份声明编码为 base64url JSON，并使用 HMAC-SHA256 对编码后的载荷签名。Qabot 在路由请求前校验签名、时间、字段类型和封闭角色集合。员工标识只来自已验证声明，会话恢复前还会核对归属。

一个按员工分组的串行执行器负责回合，因此选择当前会话的请求和直接指定该会话标识的请求不能绕过彼此的队列。不同员工的请求互不阻塞。旧 `/api` 路由在调用方迁移期间暂时保留共享服务令牌，但该令牌不定义 `/v1` 的授权方式。

`/v1` 员工路由支持创建、列出、读取、更新、归档、评价、流式生成和取消会话。流式接口发送具名 SSE 事件；取消操作会校验会话归属、调用 agent 的公开取消 API、刷新会话并释放已取消句柄，使下一回合从持久日志恢复。可由部署配置的 DeepSeek 流空闲超时默认 30 秒，独立的 Qabot 回合期限默认 45 秒，也能覆盖网关始终不返回响应头的情况。超时回合会被取消并持久化，然后返回可见兜底提示，不会让前端无限停留在生成状态。评价会校验签名员工同时拥有会话与工单，只接受解决或关闭后的首次评分，并比较工单版本。客服路由要求 Agent、DepartmentAdmin 或 SystemAdmin 角色；非系统管理员只能看到分配给其签名 `departmentIds` 所含服务组的工单。接单处理人来自已签名员工身份，工单、服务人员、知识和发布操作会追加持久审计记录。只有 SystemAdmin 可以修改服务团队成员或读取审计记录。请求体与消息长度限制会在模型执行前拒绝超限输入。身份密钥和兼容密钥均由部署环境提供，源代码与启动脚本不包含密钥值。

## Alternatives considered

- **信任 BFF 转发的身份字段：** 拒绝，因为意外开放的直连路由或代理缺陷会让调用方字段参与授权决策。
- **共享服务令牌配合归属字段：** 拒绝，因为持有一个部署密钥就能冒充所有员工和管理员。
- **全局串行执行全部模型请求：** 拒绝，因为不同员工不共享 DSH 会话状态，可以并发执行。
- **立即采用非对称 JWT：** 暂缓，因为单公司部署只有一个门户签发方和一个 Qabot 校验方，紧凑 HMAC 格式不增加外部依赖。出现多签发方或独立运营的校验服务时需要非对称签名。

## Consequences

版本化员工请求无法通过 JSON 或查询参数选择员工，猜测会话标识也不能恢复其他员工的会话。客服无法选择自己的处理人身份，也不能读取分配给其他服务组的工单。门户的员工、工单、服务人员、知识和分析操作均使用签名路由。特权修改会产生可查询的审计记录。同一员工一次只处理一个回合，代价是同时发送到该员工各会话的消息需要排队。HMAC 要求门户与 Qabot 共享并轮换一个密钥。兼容路由只保留用于直接迁移诊断，门户不再使用这些路由。
