# Agent Note: Qabot 人工服务归属与消息时间线

Status: implemented

[English](2026-08-27-qabot-human-service-timeline.md) | 中文

## Problem

自动选择服务组会在员工选择服务类型前发送转人工通知。模型轮次和人工回复随后可能争夺服务归属，而会话与工单的独立投影会按角色分组消息，不能保持实际对话顺序。作为初始化数据的服务人员记录也会在删除后重新出现。

## Decision

agent（智能体）只建议使用门户的转人工入口，不选择服务组，也不通知服务人员。持久化会话中的工具事件使智能服务工单保持开放，并自动展开门户的服务类型单选卡片；员工再次进入该会话时会恢复卡片，直到员工完成选择或取消。员工选择人事、行政、IT、财务或其他；其他映射到综合服务组。只有完成选择后，系统才写入转人工原因并将工单置为 `waiting_agent`，再创建一条带幂等键的通知任务，发送给所选服务组的全部已启用人员。工单在其中一人接单前不设置处理人。服务组没有已启用人员时，工单保持未分配状态，等待主管处理。

工单归人工服务处理时，员工消息进入工单时间线存储和模型上下文。Qabot 会先判断检索相关性：存在可靠知识命中时允许 AI 回答一次；没有命中时不启动模型轮次，由服务人员回答。人工回复进入同一份业务时间线和模型上下文，但只通过门户时间线展示给员工。

会话投影按持久化时间合并员工、智能问答和人工客服消息。时间相同时，分别使用会话序号和回复 ID 稳定排序。每条员工、智能问答和人工客服消息还会更新会话摘要的最后活动时间和可见消息数。门户按活动时间排列摘要，并在浏览器内保存每个会话的已读消息数；非当前会话新增消息后显示未读角标，直到员工进入该会话。

已有对话会恢复对应的持久会话，不会用同一 ID 创建新会话。会话发现同时识别仓库根目录和旧版 `apps/qabot` 工作目录。

服务人员 JSON 文件是一次性初始化数据源。导入完成后，服务人员数据库是真源。

## Alternatives considered

**由模型选择服务组。** 这种方式少一次员工点击，但可能派错服务组，并在员工确认转人工前发送通知。

**自动指定一名组内服务人员。** 否决，因为小型服务组可以直接协调接单，自动分配可能指定暂时无法处理的人，并让其他本可接单的组员看不到工单。

**人工服务期间继续执行模型轮次。** 这种方式可以回答已有知识的问题，但会在一个尚未解决的服务过程中混合 AI 和人工归属。新建会话为员工提供了明确的 AI 服务入口。

**通过飞书发送人工回复。** 这种方式会重复门户时间线，并增加员工在外部链路间跳转的步骤。

## Consequences

门户成为员工使用人工服务的唯一对话界面，飞书仅作为服务人员通知渠道。转接完成后，工单进入所选服务组的共享队列，该组全部已启用人员都会收到通知。第一位乐观并发接单成功的人取得工单，其他组员随后看到确定的处理人；没有已启用人员的服务组仍需主管处理。处于人工服务状态的工单只对有知识依据的问题提供 AI 回答。员工和人工消息会在 HTTP 请求完成前持久化，因此重启 Qabot 后仍保留完整时间线。跨存储时间戳提供统一展示顺序；时间精度仍是排序限制，并由持久化 ID 处理同一时间的顺序。未读状态保存在当前浏览器，不会在不同设备之间同步。首次导入后如需变更服务人员，必须显式更新数据库。
