# Agent Note: 建立受治理的 Qabot 知识中心结构

Status: implemented

[English](2026-08-27-qabot-knowledge-center-schema.md) | 中文

## Problem

Qabot 将可直接检索的分块保存在单个 SQLite 表中。飞书同步可以立即替换这些分块，因此来源变更没有草稿、审核、发布、版本历史、部门范围或可靠审计目标。

## Decision

MySQL 迁移 2 分别建立知识来源、文档、文档版本、适用部门、分块、资产、向量、审核和同步任务。文档版本使用固定状态 `draft`、`pending_review`、`published`、`archived` 和 `rejected`。内容与资产哈希作为持久字段保存。文本和视觉向量记录目标类型、模态、模型标识、维度和来源内容哈希，避免把不同模型或模态的向量当作可直接比较的数据。

数据结构将文档身份与不可变版本分离。同一文档可以存在一个待审核版本，同时继续使用上一个已发布版本。适用部门归属于版本，因为制度范围可能随发布变化。同步任务具有幂等键和处理计数；审核记录保留审核人、决定、可选说明和时间。

SQLite 检索 Provider 将同步发现的来源变更记录为 `pending_review` 版本。暂存过程保留当前已发布分块和向量。审核人通过签名知识接口发布版本；发布操作替换该来源的分块、归档上一版本，并且只计算缺失向量。被驳回的版本不会进入检索。MySQL 表作为相同生命周期和审计数据的生产投影。

## Alternatives considered

- **只给现有分块表增加状态字段：** 不采用，因为替换分块仍会在审核完成前破坏上一已发布版本。
- **只在来源配置保存审核状态：** 不采用，因为一个来源可能包含多个需要独立版本管理的文档。
- **不记录模型元数据就混合文本和视觉向量：** 不采用，因为它们的维度和相似度空间不兼容。

## Consequences

`hr_system` 包含九张受治理知识表，迁移版本 2 状态干净。所有表和字段都有中文备注。Qabot 要求同步文本经过发布后才能影响员工回答；本地运行由 SQLite Provider 保持该行为，MySQL 投影用于生产报表和后续仓储归并。文档变更进入待审核状态时，视觉资产继续使用上一已发布数据，因此同步不会在文本审核前替换员工可见图片。
