# Agent Note: 为 Qabot 工单状态迁移增加版本

Status: implemented

[English](2026-08-27-qabot-ticket-state-version.md) | 中文

## Problem

原型使用 `handoff` 表示等待人工，并且更新工单时不比较客服读取到的状态。两名客服可能从同一个过期页面接单或回复，覆盖处理人，或者在另一项状态迁移后继续追加回复。

## Decision

工单数据库结构版本 2 将已存 `handoff` 转换为 `waiting_agent`，并增加初始值为一的整数 `version`。每个状态修改操作都会递增版本。门户的接单、回复、转接、关闭和评分请求会提交最近读取的版本；SQL 同时比较状态与版本，其中任一发生变化就返回冲突。

有效服务状态为 `open`、`waiting_agent`、`in_service`、`waiting_employee`、`resolved`、`closed` 和 `reopened`，门户统一投影为待处理、待接单、处理中和已完成。纯智能 `open` 工单仅主管可见。[空闲会话关闭决策](../bug-fix/2026-09-01-qabot-accepted-conversation-idle-close.md)负责定义哪些活动状态会在无活动一小时后关闭。主管可以把 `open` 智能工单直接转给目标服务组中的已启用人员，工单随后进入 `waiting_agent`。分配不等于接单：完成路由的工单保持 `waiting_agent`，直到处理人接单。只有 `in_service` 或 `waiting_employee` 工单可以公开回复；回复会在同一事务中追加消息并进入 `waiting_employee`。状态或版本前置条件不满足时，回复事务会回滚全部修改。其他活动工单的转接使用相同目标要求，系统清除原处理关系、分配所选人员，并使工单回到 `waiting_agent`。

工单数据库使用 SQLite `user_version` 作为单调迁移计数器。版本一数据库只执行一次新增字段和状态转换；结构版本三删除 `satisfaction_note`。员工门户只接受数字评分，因此 Ticket 不包含服务评论字段。员工评分接口会校验会话归属、工单 ID、分数和最近读取的工单版本，但不会向员工开放客服关闭工单操作。新数据库按相同顺序执行迁移。PostgreSQL 迁移 002 会在初始结构后删除对应字段。

## Alternatives considered

- **最后写入覆盖：** 拒绝，因为分配和员工可见回复属于业务操作，冲突需要处理人作出决定。
- **比较时间戳：** 拒绝，因为时间戳精度和时钟语义不能表达调用方读取的是哪个存储版本。
- **客服打开页面时锁定工单：** 拒绝，因为浏览器锁容易遗留并阻碍正常读取；乐观比较只协调修改操作。
- **永久保留 `handoff` 状态：** 拒绝，因为它描述一次事件，而 `waiting_agent` 描述路由与可见性规则使用的服务组共享队列。

## Consequences

并发客服修改和过期的员工评分会返回 HTTP 409，不再静默覆盖。客户端必须保存并提交 `version`，冲突后刷新工单。已分配的服务人员必须先接单，页面才开放回复和结束服务；不适合本人处理的工单可在接单前指定下一位处理人并转接。员工只能通过员工接口评价自己的已关闭会话，客服关闭权限保持独立。已有工单数据库会迁移 `handoff` 记录并丢弃未使用的服务评论列，无需重建数据库。直接调用兼容接口时，接单、转接和关闭仍可省略版本，因此这些调用不属于版本化并发保证。
