# Agent Note: Qabot 服务组共享待接单队列

Status: implemented

[English](2026-08-31-qabot-shared-group-queue.md) | 中文

## Problem

单张工单优先级、可配置 SLA 截止时间和自动指定处理人，是为公司当前并不存在的工单量增加运营控制。额外字段和配置页面让小型服务组花时间管理策略，而不是直接回答员工；自动分配还可能选中唯一暂时无法处理的人，却不给同组其他人接单机会。

## Decision

员工转人工时，工单只进入服务组，不设置优先级、SLA 截止时间或处理人。一条带幂等键的 Outbox 任务把转人工卡片发送给服务人员配置中该组的全部已启用人员。工单保持在服务组共享的 `waiting_agent` 队列，直到其中一人通过现有乐观版本校验接单。第一次成功接单会写入处理人，并阻止其他人用同一版本重复接单。

客服主动转接与员工转人工不同：客服需要同时选择目标服务组和具体接收人，因为这是已有负责人显式移交责任。

MySQL 迁移 006 删除迁移 005 引入的优先级与 SLA 投影，并删除服务策略表。门户移除独立后台配置页，把审计记录展示在运营分析中。审计日志继续记录工单、知识与服务人员操作；系统不再存在需要记录的优先级修改。

## Alternatives considered

**保留优先级，只在门户隐藏。** 否决，因为隐藏字段和接口仍会保留无人维护的运营规则和无效数据库状态。

**只通知一名自动选中的服务人员。** 否决，因为自动选择不知道人员是否可用，而预期的服务组规模足够小，可以让全部成员获得相同接单机会。

**随配置页面一起删除审计日志。** 否决，因为知识发布、服务人员配置、工单转接和关闭仍是需要追溯责任的特权操作。运营分析是审计信息的展示位置。

## Consequences

每张新转人工工单都会向所选服务组全员展示和通知，第一位成功接单的人取得处理权。Outbox 幂等键继续限制重复通知。服务台页面不再展示或配置优先级与 SLA。系统放弃按截止时间升级和紧急程度排序；按时间排列的队列与现有四种工单状态足以支撑预期工作量。
