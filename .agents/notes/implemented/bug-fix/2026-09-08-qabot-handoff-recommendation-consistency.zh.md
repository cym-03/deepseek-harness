# Agent Note: 保持 Qabot 转人工建议一致

Status: implemented

[English](2026-09-08-qabot-handoff-recommendation-consistency.md) | 中文

## Problem

模型可能在文字中判断事项需要人工处理，却没有调用 `request_human_handoff`。员工能看到联系人工的文字，但界面不提供转人工入口。测评集还使用一个转人工布尔值同时表示正常回答、知识缺失、安全拒答、业务范围外和必须人工办理，导致汇总分数无法反映真实问题。

## Decision

模型提示词要求回答判断需要人工处理时必须调用 `request_human_handoff`，并在调用后的可见回复中写明 `推荐人工处理`。Qabot 还会识别完成回答中措辞明确的人工处理建议，并在即时响应和重建会话中给出相同的转人工推荐。只提到人工服务时间或由人员审批，不会触发补偿判断。

员工服务测评数据为每个案例记录 `normal_answer`、`manual_required`、`knowledge_missing`、`safe_refusal` 或 `out_of_scope`。人事、财务、IT、行政、考勤和视觉内容各至少包含三道题，文字关键词与预期视觉主题分别断言。

## Alternatives considered

**只信任工具调用。** 未采用，因为模型可能给出有效回答并明确建议人工处理，却遗漏工具调用，导致界面行为与文字不一致。

**所有拒答或无法回答都转人工。** 未采用，因为安全拒答和员工服务范围外问题属于不同结果，不一定应创建内部服务请求。

**匹配所有“人工”字样。** 未采用，因为人工服务时间和人工审批步骤会产生错误推荐。

## Consequences

回答明确判断需要人工处理时，即使模型遗漏工具调用，界面也会可靠展示转人工选择，并在刷新会话后保持一致。补偿匹配有意保持严格，仍可能遗漏新的表达方式，因此提示词是主要机制，测试固定允许和拒绝的措辞。测评报告可以分别衡量回答质量、路由、安全、范围和视觉精准度，不再压缩为一个百分比。
