# Agent Note: 按角色隔离的智能问答运营驾驶舱

Status: implemented

[English](2026-09-07-role-scoped-operations-dashboard.md) | 中文

## Problem

原周报混用了近似时间、内部审计编码、工单首问和未隔离的全局统计。它无法区分 AI 建议转人工与员工实际进入人工服务，也无法保存可配置直答内容。

## Decision

Qabot 将有效提问轮次、建议和实际转人工事件、常见问题、附件、使用记录、员工声音缓存及统一审计行持久化到 MySQL。报表使用 Asia/Shanghai 时区的左闭右开时间范围，并与前一个等长周期比较。工单服务领域从持久化依据重新计算，依次采用实际人工分组、常见问题命中和最强可靠知识来源。未命中问题和有文字内容的低评分评价在所属服务组内合并相似表达，使措辞差异归入同一运营问题；没有文字评价的低分仍纳入满意度指标和员工声音，但不纳入差评原因归因。领域指标对每张会话工单只计算一次；转人工率以实际由员工选择转人工的会话为分子，以同周期全部会话为分母。核心解决时长对有效服务处理区间取平均值，不包含会话等待关闭期间的闲置时间。

主管可查看全部或单个分组。人事、行政、IT、财务专员无论请求参数如何，都会由服务端限定为角色对应分组。运营分析只呈现总览，包括带悬浮口径说明的四项数值指标、按人工和机器人服务切分的可筛选会话表、紧凑归因面板，以及员工提交的每条评分与评价内容。会话表使用当前报表时间范围，每页显示十条，并可从表格行打开授权范围内的工单依据。满意度指标与员工声音按评价提交时间筛选，不使用工单创建时间。常见问题配置是智能问答后台的同级板块；仅主管可见的服务端分页审计放在门户“数据报告”中，不在智能问答后台展示。

归因结果保留授权范围内的工单标识，运营人员可打开对应会话，同时摘要中不展示员工姓名。转人工分组由文本模型根据员工、智能助手和人工客服的完整会话生成简短的业务原因标题；上文已有未解决需求时，不把转人工动作本身当作原因。总览立即返回已缓存或基于依据的确定性标题，并在后台刷新缺失的模型归纳，因此模型延迟不会阻塞指标和表格。进程内依据哈希复用未变化的结果。筛选后的报告以 UTF-8 CSV 导出，包含周期、核心指标、分领域表和归因依据。

知识同步和常见问题变更失败时，会在向调用方返回原始错误前向统一审计追加可读的失败记录。审计写入自身失败会单独报告，不会替换业务错误。

未命中排行只纳入没有可靠常见问题或知识答案，并且 Qabot 同时发出人工服务建议的有效提问。模型生成了回答但没有建议转人工的提问，不归类为未命中。

每组最多启用五条常见问题，限制在数据库事务中执行。完全一致的问题，以及达到高阈值且明显领先第二候选的问题，会直接返回已保存答案、最多三张 MySQL 图片和最多五个链接，不调用模型。其他问题继续使用普通知识检索和模型问答。

## Alternatives considered

**继续扩展固定周报** —— 未采用，因为其工单级投影无法在不产生口径冲突的情况下表达逐轮知识依据、实际转人工选择、角色隔离和任意时间范围。

**将每次 AI 转人工建议都算作转人工** —— 未采用，因为员工未选择服务组、未进入队列时会虚增人工服务需求。

**常见问题始终使用语义匹配** —— 未采用，因为弱匹配可能绕过完整知识系统并返回错误的固定答案。语义直答必须同时满足高阈值和领先幅度。

**将常见问题图片保存到磁盘** —— 未采用，因为产品要求 MySQL 继续作为运营配置及附件的可恢复权威数据源。

## Consequences

运营结果可以从持久化记录复算，权限由服务端保证，常见问题可在不消耗模型额度的情况下直接回答。历史关闭时间仍是估算值，但不会抬高有效处理时长平均值。保守直答匹配会将模糊问题交给普通检索，虽然成本更高，但可以避免错误直答。由于原始图片二进制被有意保留，需要监控 MySQL 附件容量。

## Verification

单元测试覆盖有效提问过滤、直答标准化、相似问题聚类、领域优先级、按角色限定的运营输入和每组常见问题限制。MySQL 迁移检查覆盖结构规范及启动迁移。门户构建和浏览器测试覆盖时间与分组筛选、归因面板、常见问题、直答附件和每页十条审计。
