# Agent Note: 持久化 Qabot 评价并提炼知识缺口

Status: implemented

[English](2026-09-02-qabot-feedback-and-knowledge-gap-analytics.md) | 中文

## Problem

单独的满意度分数无法解释员工满意或不满意的原因。运营报告只统计每张工单的首个问题时会丢失大部分会话上下文，原始审计标识也不便于门户用户日常查看。

## Decision

工单在一至五分的必选分数旁持久化可选的满意度评价。员工评价卡片一次提交这两个值，周度运营报告展示每条评分及其可选评价内容。

报告从纳入统计的每段会话中读取全部已持久化员工消息，并据此提炼相近问题类型。本地确定性归一化结合字符相似度与稳定的员工服务主题规则，生成报告时不调用向量模型或语言模型，并排除问候、确认、测试和转人工指令。发生转人工的会话将最后一条实质性员工问题标记为转人工关联问题；即使该类问题只出现一次，也保留在聚类结果中，因为它代表潜在知识缺口。

门户将已知审计操作、操作人员和资源类型转换为中文标签。未知值显示可读的兜底名称，同时在标题中保留原编码供排查。审计记录在前端按每页十条分页。

## Alternatives considered

**每次生成报告都调用模型总结和聚类** — 未采用，因为刷新报告会消耗模型额度，并产生不稳定的归类结果。当前服务量使用本地确定性归类已经足够。

**只保留工单首个问题** — 未采用，因为后续问题经常才是触发转人工的原因，也包含更有价值的知识缺口信号。

**把文字评价存入审计详情** — 未采用，因为评价属于工单业务数据并用于报表，不应依赖审计展示才能长期保存。

## Consequences

运营人员可以查看评分及评价内容，将相似问题作为一个热点，并优先补充与转人工相关的问题类型。归类规则有意保持克制，新业务主题大量出现时需要维护规则。审计分页只处理接口返回的最近记录，不增加新的服务端分页协议。

## Verification

存储测试覆盖 SQLite 迁移和评价内容持久化，报告测试覆盖相近问题归类以及单次转人工知识缺口。门户浏览器测试覆盖可选评价提交、历史持续展示、可读审计标签、运营评价内容、转人工标记和每页十条分页。
